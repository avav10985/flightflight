# B 案:Nano 對照組(Brokking YMFC-AL)接線與燒錄

> 目的:用一台**已知會飛**的參考飛控當基準,判斷「飛不好」是軟體問題還是機架問題。
> 建立:2026-09-07

## 為什麼要做這個

現在無法判斷問題出在哪。跑 Brokking 的 YMFC-AL:
- **飛得好** → 機架/馬達/ESC/槳都沒問題,錯全在我們的 ESP32 軟體
- **還是爛** → 問題是機械的(振動、重心、槳、馬達)

---

## 系統架構

```
舊 Nano 手把 ──nRF24──> RX Nano ──4路 servo PWM──> FC Nano ──> 4× ESC
  (不改)      pipe 4E6F9C2D5B   D2~D5 → D8~D11    (YMFC-AL)
              ch88 / 250kbps                        原版不改
```

**手把不用改**:同一隻手把既能飛真飛機(`Drone_FC_Full`)也能飛這台,切換不用重燒。
V2 的 ESP32-S3 手把協定相同,也能直接用。

## 電源樹(⚠️ 這裡最容易做壞)

```
飛行電池 ──> ESC ──BEC 5V──┬──> Nano #1 的 5V 腳
                            ├──> Nano #2 的 5V 腳
                            ├──> MPU6050 VCC
                            └──> AMS1117-3.3 ──> nRF24 VCC (3.3V)
                                                  ‖
                                            100µF + 0.1µF
GND 全部共地
```

### ⚠️ nRF24 不要吃 Nano 的 3V3 腳

Nano 板上的 3V3 是從 CH340/FT232 晶片內部取的,**很多副廠板只有幾十 mA**,
PA/LNA 版 nRF24 在 TX 瞬間會把它拉垮 → 通訊時好時壞、隨機斷線。

**這個坑你已經踩過兩次**(V2 手把 S3 的 LDO 撐不住、3V3 軌要升級),不要再踩第三次。
花 NT$10 用獨立 AMS1117-3.3,並在 nRF24 腳邊補 **100µF + 0.1µF**。

> 只是桌面短距離測試的話,直接吃 3V3 腳 + 100µF 也許撐得過,
> 但這台要飛,**照上面做**。

### Nano 供電注意
- 用 **5V 腳**直接餵 5V(繞過板上穩壓),**不要**從 VIN 餵 5V(會掉到 3.5V 左右)
- 燒錄時插 USB,此時**拔掉 BEC 5V**,避免兩個電源對灌

## 接線

### Nano #1(接收橋接)—— 燒 `測試程式/Nano對照組/NRF24_to_PWM/`

| Nano #1 | 接到 | 說明 |
|---|---|---|
| D9 | NRF24 CE | |
| D10 | NRF24 CSN | |
| D11 | NRF24 MOSI | |
| D12 | NRF24 MISO | |
| D13 | NRF24 SCK | |
| — | **NRF24 VCC ← AMS1117-3.3 輸出** | ⚠️ 不是 Nano 的 3V3 |
| GND | NRF24 GND | |
| 5V | BEC 5V | |
| D2 | → #2 的 **D8** | ch1 = roll |
| D3 | → #2 的 **D9** | ch2 = pitch |
| D4 | → #2 的 **D10** | ch3 = throttle |
| D5 | → #2 的 **D11** | ch4 = yaw |
| GND | → #2 的 GND | **共地必接,不接會讀不到脈寬** |

### Nano #2(飛控)—— 燒 Brokking 原版

| Nano #2 | 接到 | 說明 |
|---|---|---|
| D8~D11 | 來自 #1 的 D2~D5 | 接收機輸入(PCINT0~3) |
| **D4** | ESC 1 訊號 | 右前 CCW |
| **D5** | ESC 2 訊號 | 右後 CW |
| **D6** | ESC 3 訊號 | 左後 CCW |
| **D7** | ESC 4 訊號 | 左前 CW |
| A4 | MPU6050 SDA | |
| A5 | MPU6050 SCL | |
| 5V / GND | MPU6050 VCC / GND | |
| **A0** | **接 GND** | ⚠️ **必接,見下** |
| D12 | 警示 LED(選用) | 板載 D13 已被佔,D12 可外接 |
| 5V | BEC 5V | |
| GND | ESC 地線共地 | |

### ⚠️ A0 一定要接 GND

飛控程式用 A0 讀電池電壓,而且會拿它**補償四顆 ESC 的輸出**:

```c
if (battery_voltage < 1240 && battery_voltage > 800){
  esc_1 += esc_1 * ((1240 - battery_voltage)/(float)3500);   // 四顆全補
```

**A0 空接 = 浮空腳讀雜訊**。雜訊一旦落進 800~1240 區間,它就拿雜訊去改油門
→ **馬達輸出亂跳**,而且在拘束架上極難查出原因。

接 GND 後 `analogRead(0)=0` → `battery_voltage=80`,低於 800 不補償、
低於 600 不亮警示燈,整段乾淨跳過。

> 之後想要電壓補償再拉分壓電阻,但**第一版先接 GND**,少一個變數。

## 實體配置

```
        ┌─────────── 洞洞板(可整片換上機架)───────────┐
        │  [Nano #1 橋接]   [Nano #2 飛控]            │
        │   + nRF24          + AMS1117                │
        │        4 訊號線 + GND 短接                   │
        └──┬────────────────────┬─────────────────────┘
           │                    │ 4× ESC 訊號
      MPU6050(短線外接)       到四支馬達
      機架中心 + 防震泡棉
```

**三個要點:**

1. **MPU6050 用短線(<10cm)外接**,貼在**機架中心**、墊防震泡棉。
   不要直接焊在洞洞板上跟著兩顆 Nano 一起震。
2. **MPU6050 要裝平**(水平)。朝向哪一邊無所謂 —— Brokking 的 `setup`
   程式會自動偵測軸向並寫進 EEPROM,但**水平度**決定了自穩的零點。
3. **Nano 做成可插拔**(排母座),因為燒錄要拔下來接 USB。

### 🔴 裝在同一台機架

MPU6050 的位置、減振方式,**盡量跟現在 ESP32 那顆一樣**。
不然振動條件不同,比較出來的結果不能說明問題。

## 燒錄順序(⚠️ 順序不可調換)

> **全程橋接 Nano #1 要通電、手把要開著。**
> Brokking 三支程式**全部**都讀 D8~D11 的接收機訊號 —— 包含 ESC 校準和 setup。
> 沒有訊號它們不會動。

### 步驟 0:先燒橋接、確認通訊
1. Nano #1 燒 `測試程式/Nano對照組/NRF24_to_PWM/`
2. Serial Monitor **115200**
3. 開手把 → 應看到 `LINK T0 R127 P127 Y127 M0`
4. 推搖桿 → 數字要跟著動

**❌ 沒有 LINK 就不要往下做**,後面每一步都靠它。

### 步驟 1:setup(⚠️ 拔槳)—— **必須第一個做**
Nano #2 燒 `YMFC-AL_setup.ino`,照 Serial 提示逐支推搖桿。

它會偵測**通道對應 + 正反向 + 陀螺儀軸向**,寫進 EEPROM,
最後寫入簽名 `'J','M','B'`。

> **為什麼一定要先做**:後面兩支程式開頭都有
> `while(eeprom_data[33]!='J' || [34]!='M' || [35]!='B')` —— 沒有這個簽名
> 就**無限等待**,燒進去像當機一樣毫無反應,而且不會告訴你原因。
> 通道對應也是這步建立的,所以接線順序接錯也沒關係,setup 會校正。

### 步驟 2:ESC 油門行程校準(⚠️ 拔槳)
Nano #2 燒 `YMFC-AL_esc_calibrate.ino`。

它的做法是**油門直通**:`esc_1..4 = 油門通道`,搖桿推多少就直接送給 ESC。
所以校準是用**手把的油門桿**操作,不是 Serial 指令:

1. **拔掉所有螺旋槳**
2. 油門桿**推到最高**
3. 插上飛行電池 → ESC 嗶聲(記住最高點)
4. 油門桿**拉到最低** → ESC 再嗶(記住最低點)→ 入彈長嗶
5. 拔電池

其他 Serial 指令(校準完可用):`r`=看接收機數值、`a`=看姿態角、
`1`~`4`=單顆測馬達、`5`=全部一起。**測馬達前確認槳是拔掉的。**

> 這跟我們 ESP32 那台的 `esccal`/`esccalmin` 是同一件事的不同實作,
> **兩台各自校準,不共用**。

### 步驟 3:飛控
Nano #2 燒 `YMFC-AL_Flight_controller.ino`。

**先拔槳通電**,確認四顆馬達會照搖桿反應且方向正確,再裝槳上拘束架。

### 步驟 4:調 PID
用 [PID調校步驟.md](PID調校步驟.md) 的**方法**,但**增益用他的預設值**
(`P 1.3 / I 0.04 / D 18.0`)—— 那是給 rate PID 用的,**絕對不要跟我們的混用**。

## ⚠️ 裝機時最重要的一件事

**Nano 飛控必須裝回「同一台機架」** —— 同樣的馬達、ESC、槳、機身。

B 案的全部價值就是這個對照:
- 同機架 + 他的程式**飛得好** → 機架沒問題,錯在我們軟體
- 同機架 + 他的程式**還是爛** → 機械問題(振動/重心/槳/馬達)

**如果另外組一台新的,這個實驗完全沒有意義** —— 兩台不同的機器,
差異可能來自任何地方,證明不了原本那台的問題在哪。

## 兩個容易搞混的點

1. **50Hz vs 250Hz**:#1 輸出給 #2 的是 50Hz 標準 servo PWM(所有遙控接收機都這規格);
   #2 送給 ESC 的才是 250Hz。這是兩條不同的鏈路,不衝突。
2. **增益不可互抄**:他是 rate PID(誤差=deg/s),我們是角度 PID(誤差=deg)。
   詳見 [PID調校步驟.md](PID調校步驟.md) 開頭。
